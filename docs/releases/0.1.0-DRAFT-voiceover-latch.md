## What changed

**Bear correction now stops itself when VoiceOver is used, and says so.**

With VoiceOver enabled, Bear stops replacing selected text and instead inserts
the replacement beside the selected original. That breaks the rule this app is
built on — replace the smallest safe range, never more — and it is not
reversible by changing the replacement range back, because the original is
still sitting there. The altered behaviour lasts for the rest of the macOS
boot; switching VoiceOver off does not restore it.

Rather than write and hope, Typover now refuses. The moment VoiceOver is
observed, every Bear mutation path declines for the remainder of the boot:
automatic correction, the overlay preview, Change Back, and alternatives. The
Bear status row reads *Paused after VoiceOver use; restart your Mac to resume
Bear correction. Typover's editor remains available.* The controlled AppKit
editor is unaffected and keeps correcting normally.

The pause is keyed to `kern.bootsessionuuid`, a true per-boot identity.
`kern.boottime` was rejected for this: macOS recomputes it as wall clock minus
uptime, so it shifts when the clock is adjusted or the Mac sleeps and wakes,
and a single shifted second would have released the pause while Bear was still
unsafe to write to.

One related change on the ordinary path: a write whose verification failed is
no longer re-anchored by re-reading the replacement range. That recovery could
promote a beside-insertion into a correction advertised as reversible when it
is not. Such writes now open the mutation circuit instead, which is the
existing, honest handling for an indeterminate write.

## Privacy or permission changes

None. The permissions required are unchanged, and the pause is decided locally
from `NSWorkspace.isVoiceOverEnabled` and a boot identifier. Nothing about
VoiceOver use leaves the Mac.

## Persisted-data changes and rollback compatibility

One new preference key, `bear-voiceover-safety-pause-boot`, holding a boot
session UUID and nothing else. Rolling back to `20260808224257` leaves the key
unread and harmless; rolling forward again re-evaluates it against the current
boot. No learning formats or existing preference keys changed, so the qualified
update, rollback, soak, and uninstall evidence remains applicable.

## Known limitations

- **Bear correction is unavailable under VoiceOver and stays unavailable until
  the Mac restarts.** This is deliberate: the alternative is a write Typover
  cannot reverse. Typover's own editor continues to work.
- Bear correction is post-pause and can safely skip when focus, selection,
  timing, text, or geometry is ambiguous.
- Bear squiggles are non-native overlays and hide when their exact anchor is
  not verifiable.
- The fast event-tap lane is research-only; its measured envelope does not
  broaden the public compatibility claim.
- Pointer-only hover timing, Reduced Motion, and the remaining Bear
  proximity/wrapped-line interaction observations are still release gates.
